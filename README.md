# FMM 团队排班

基于现有 FMM React 前端的 AstrBot 插件，使用 Python + SQLite，运行时不需要原有 Go、MySQL、Redis 或七牛服务。

## 仓库内容

本仓库只提交源码：

- 根目录：AstrBot 插件 Python 源码、配置和运行依赖。
- `frontend/`：React + Vite 前端源码。
- `web/`：本地构建输出，不提交到 Git。

## 原版页面

直接复用原 React 项目的成员档案卡片、统计、搜索筛选、字段管理、Excel 导入、花名册导出和任务管理组件及样式，在原界面上增加 QQ 必填绑定、“群提醒”和“发送记录”页。原页面接口通过插件兼容层接入 SQLite。

成员、字段、排班、发送记录、花名册导出历史和任务数据均保存在 SQLite。任务页仅在数据库尚无任务工作区时读取当前浏览器原有的本地任务数据，之后保存到数据库；旧 Go 系统数据库不会自动迁移。任务工作区采用整体保存，请避免多位管理员同时编辑任务。

## 安装

1. 使用 AstrBot 4.5.0 或更新的 4.x 版本，Python 3.10+，配置好 OneBot V11（`aiocqhttp`，例如 NapCat）。机器人需要已加入目标 QQ 群。
2. 将插件部署到 `AstrBot/data/plugins/astrbot_plugin_fmm/`。确保该目录下直接包含 `main.py`、`metadata.yaml`、`requirements.txt` 和 `web/`，不要多套一层目录。发布包应已完成前端构建；直接使用本源码仓库时，需要先按照下文的构建步骤生成 `web/`。
3. 在 AstrBot 使用的 Python 环境安装 `requirements.txt` 依赖，在插件管理中重载/启用插件。
4. 在插件配置中设置至少 12 位的 `web_password`，打开 `http://服务器地址:8765/` 登录。密码留空时自动生成在下面的数据目录中。

插件配置项：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `web_host` | `127.0.0.1` | 监听地址；容器内可设置为 `0.0.0.0` |
| `web_port` | `8765` | 独立管理页面端口 |
| `web_password` | 空 | 至少 12 位；留空时生成 `admin_password.txt` |
| `sync_group_id` | `629409123` | 群成员同步默认使用的 QQ 群号；留空则每次在弹窗里选 |
| `sync_class_field` | 空 | 把群名片里的班级写进哪个自定义字段的 ID；留空则自动找名为「专业班级」的字段 |

Docker 部署需要映射管理端口，并持久化 AstrBot 的 `data` 目录。管理页没有内置 HTTPS，不要直接暴露到公网；远程访问建议使用 SSH 隧道、内网或 HTTPS 反向代理。反向代理须保留原始 Host，前后端使用同一来源。

## 群成员同步

成员档案页工具栏的「同步群成员」按钮把 QQ 群成员同步进档案，分两步：先算出差异（新增 / 修改 / 退群）给人看，确认之后才写入。预览本身不落库、不下载图片。

- 群名片按 `专业班级 + 姓名（小名）[部门]` 解析：`数管2602周晨希（粥粥）[P]` → 姓名 周晨希、专业班级 数管2602、小名 粥粥、部门 P；多部门 `[M&C]` 写成 `M、C`。解析出的属性会写入**同名的自定义字段**（`专业班级` / `小名` / `部门`），字段不存在就跳过；`sync_class_field` 可以显式指定专业班级字段的 ID。没有群名片的用 QQ 昵称当姓名，其余属性留空，不猜。
- 性别按 OneBot 返回的 `sex` 填。很多群对全员返回 `unknown`，这时一律填「未知」，不根据名字猜。
- 照片在确认之后才下载，存进插件的上传目录，不依赖 QQ 的头像 CDN。
- 退群（档案里有、群里已不在）默认标记为「光荣退休」，也可以选择删除档案或本次不处理；已经标记过的不再重复出现。
- 确认前后只要群成员有变动就拒绝执行，并把重新算出的差异摆回来让人再确认，避免按过期名单动手；退群人数达到现有档案一半时会额外要求勾选确认。
- 新增、改名、改班级、状态变更、照片更换都会写进成员的修改历史。
- 群成员用机器人自己已登录的 OneBot 连接读取，机器人需要在目标群里。列表里只会出现机器人已加入的群。

## 成员与排班

- 成员档案的姓名、QQ 号、性别和状态必填；QQ 号必须唯一。此处填写的 QQ 号就是群消息中的 `@` 目标，不需要另行绑定。
- 每个排班有独立的机器人账号、目标群、提醒时间、开始日期、执行星期、有序人员池和每次人数。
- 人员池使用“上移/下移”调整顺序。例如池为 A、B、C，每次 1 人会按 A → B → C → A 轮换；每次 2 人则为 AB → CA → BC。
- 同一个成员可以加入多个排班，各排班轮换位置独立。离职或退休成员会被跳过；在职人数不足时该次不发送，页面显示错误。仍在人员池中的成员不能直接删除。
- 群提醒卡片可直接手动选择“下一轮起点”。例如当前是 A，选择 C 后下一轮就从 C 开始，并继续按人员池顺序轮换；存在未处理发送记录时需先处理。
- 附加文案支持 `{date}`（北京时间日期）、`{names}`（本轮姓名）、`{schedule}`（排班名称）。`@` 使用结构化 OneBot 消息段，文案中的 CQ 字符串不会被当成指令。
- 新建排班默认暂停。保存前勾选“启用排班”或使用列表开关开启。
- “测试发送”会向真实目标群发送标有测试字样的消息，但不推进轮换。在本地独立预览模式下只会记录失败，不会发送 QQ 消息。

## AI 自然语言管理

插件通过 AstrBot 原生 `@llm_tool` 注册管理工具，复用 AstrBot 当前配置的 LLM Provider，不需要另外填写 OpenAI API Key，也不启动独立 AI 服务。

所有 AI 工具（包括查询和预览）都只允许 AstrBot 管理员使用。服务端会同时校验真实消息发送者、平台、会话、AstrBot 的 `is_admin()` 结果，以及该会话当前 `admins_id` 中的发送者 ID；任一项无法确认就拒绝。QQ 群管理员、群主、聊天中自称管理员或工具参数中的角色标记都不会授予权限，AstrBot 管理员身份被撤销后也不能继续执行待确认操作。

只读工具：

- `fmm_find_members`：按姓名、QQ 或状态查询成员。
- `fmm_list_schedules`：列出排班及下一轮成员。
- `fmm_get_schedule`：查看排班配置、有序人员池、当前位置和下一轮成员。
- `fmm_preview_rotation`：只读预览接下来若干轮，不修改轮换位置、不发送消息。
- `fmm_get_send_records`：查询群提醒发送历史和失败记录。

需要确认的修改工具：

- `fmm_create_member`、`fmm_update_member`：创建或修改成员档案。
- `fmm_create_schedule`、`fmm_update_schedule`：创建或修改排班；新建排班默认暂停。
- `fmm_manage_pool_member`：把已有成员加入或移出排班人员池，不删除成员档案。
- `fmm_move_member`：向前、向后、移动到某人前后、第一位或最后一位。
- `fmm_confirm_change`：提交管理员明确确认的待执行修改。

修改工具第一次调用只返回预览和确认 ID，不写入数据库。确认记录保存在插件进程内，绑定原管理员、平台和会话，10 分钟后过期且只能使用一次；同一管理员和会话只保留最新一条，插件重启后全部失效。确认时会重新检查管理员权限、成员档案或排班版本、未处理发送记录及原有业务约束。调整人员池顺序时会保持当前下一轮成员不变（该成员仍在池中时）。

QQ 中可以直接尝试：

- “查一下张三的成员档案和 QQ。”
- “把张三加入晚班。”
- “把张三往后移动两位。”
- “把李四移动到王五后面。”
- “把晚班提醒时间改成晚上八点，然后预览接下来五轮。”
- “新建一个周三晚班提醒，先保持暂停。”
- “查看最近的发送失败记录。”
- “确认刚才的修改。”

管理员身份请在 AstrBot 管理面板的 `admins_id` 中配置；不要通过群聊消息或 LLM 参数设置权限。AI 工具已使用 AstrBot 4.9.2 的原生接口和 Mock 权限事件覆盖自动化测试，真实 NapCat/AstrBot 中的 Provider 工具选择、群聊确认和管理员撤销仍需在部署环境手工验证。本地独立预览模式不加载 AstrBot，因此不能在本地网页预览中测试 QQ 自然语言工具。

## 定时与故障处理

- 统一使用 `Asia/Shanghai`（北京时间），每个排班每天最多一次正式发送。
- 只有成功返回消息 ID 或管理员确认已发送，才推进轮换。插件重启不会重置轮换位置。
- 明确拒绝发送记为“发送失败”；超时、网络异常、发送中重启等情况记为“结果待确认”。这些正式记录会阻塞后续发送和排班修改，避免不确定情况下重复提醒。
- 在“发送记录”先核对群消息，再选择“确认已发送”或“跳过本次”。跳过不会推进轮换，也不会当日重发，下次仍选本轮人员。插件不自动重试失败消息。
- 重启时只补发今天计划时间后 10 分钟内的提醒；更早的错过提醒不追溯，下一次仍从当前人员开始。
- 最近 200 条记录之外，未处理记录仍会保留在页面中。历史记录保存发送时的姓名、QQ 和文案快照。
- 单实例运行。不要让多个进程或多个 AstrBot 实例同时使用同一数据库。

## 数据与备份

数据目录由 AstrBot `StarTools.get_data_dir` 提供，通常为：

```text
AstrBot/data/plugin_data/astrbot_plugin_fmm/
  fmm.sqlite3
  admin_password.txt
  uploads/
```

顶部下载图标提供 SQLite 在线一致性备份，包含已提交 WAL 内容，但不包含上传图片。完整备份还需保存 `uploads/`。恢复时先禁用插件，保留原文件备份，用下载文件替换 `fmm.sqlite3`，确认没有遗留的旧 `-wal/-shm` 后再启动。没有网页恢复入口。

Excel 导入使用页面模板；整批数据原子保存，缺少 QQ 或 QQ 重复时整批不写入。已有旧系统数据不会自动迁移，建议导出后补齐 QQ 号再导入。

## 本地预览与开发

在整个工作区的根目录执行：

```bash
python -m pip install -r astrbot_plugin_fmm/requirements.txt
python -m astrbot_plugin_fmm.dev --port 8765
```

打开 `http://127.0.0.1:8765/`，密码在 `.fmm-preview/admin_password.txt`。也可以通过环境变量 `FMM_WEB_PASSWORD` 指定预览密码。此模式不依赖 AstrBot，且不会发送 QQ 消息。

前端源码位于 `frontend/`，构建产物自动写入插件根目录的 `web/`。服务器运行插件时不依赖 Node.js，但自行从源码部署前需要先完成构建：

```bash
cd frontend
npm ci --no-audit --no-fund
npm run build
```

工作区根目录运行后端回归测试与打包：

```bash
python -m pytest tests -q
python scripts/package_plugin.py
```

自动测试覆盖 SQLite 和 Web 接口；真实群投递仍需要在已连接 OneBot 的 AstrBot 环境中验证。
